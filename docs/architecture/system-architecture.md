# システムアーキテクチャ設計書

## 1. 概要

ラクフクは、毎朝1分で最適なコーディネートを提案するAIスタイリストアプリです。

### 1.1 設計原則

| 原則 | 説明 |
|------|------|
| シンプルさ | MVP優先、過剰な機能を避ける |
| スケーラビリティ | Cloud Runによるオートスケール |
| 低レイテンシ | ユーザー体験を損なわない応答速度（目標: 3秒以内） |
| オフラインファースト | 基本機能はオフラインでも動作 |

## 3. コンポーネント詳細

### 3.1 Flutter Application

| コンポーネント | 技術 | 役割 |
|---------------|------|------|
| UI Framework | Flutter 3.x | クロスプラットフォームUI |
| State Management | Riverpod | 状態管理 |
| HTTP Client | Dio | API通信 |
| Local Storage | Hive | オフラインキャッシュ |
| Image Picker | image_picker | カメラ/ギャラリーアクセス |

### 3.2 Cloud Run Backend

| コンポーネント | 技術 | 役割 |
|---------------|------|------|
| Framework | FastAPI | REST API |
| AI Agent | Google ADK | エージェント基盤 |
| LLM | Gemini 2.0 Flash | 推論エンジン |
| Auth | Firebase Auth | 認証 |

### 3.3 Data Layer

| ストア | 用途 |
|--------|------|
| Firestore | ユーザーデータ、クローゼット、履歴 |
| Firebase Storage | 服の画像 |
| Cloud Memorystore | セッションキャッシュ（将来） |

## 5. 非機能要件

### 5.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| API応答時間（P95） | < 3秒 |
| アプリ起動時間 | < 2秒 |
| 画像アップロード | < 5秒 |

### 5.2 可用性

| 指標 | 目標値 |
|------|--------|
| 稼働率 | 99.5% |
| 計画メンテナンス | 月1回以下 |

### 5.3 セキュリティ

| 項目 | 対策 |
|------|------|
| 認証 | Firebase Authentication |
| 通信 | HTTPS必須 |
| データ | Firestore Security Rules |
| 画像 | Firebase Storage Security Rules |

## 6. スケーリング戦略

### 6.1 Cloud Run オートスケール

```yaml
# Cloud Run設定
min_instances: 0
max_instances: 10
concurrency: 80
cpu: 1
memory: 512Mi
```

### 6.2 コスト最適化

| 戦略 | 説明 |
|------|------|
| コールドスタート対策 | min_instances: 1（本番時） |
| キャッシュ活用 | 天気データ15分キャッシュ |
| バッチ処理 | フィードバック集計は非同期 |
